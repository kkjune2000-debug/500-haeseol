`놀라운 한국어 500 해설집\말하기_PPT`의 4개 PPT(말하기_1_문장구조 / _2_서술어문법 / _3_부사어문법 / _4_기타문법). 각 문장마다 문제·정답 2슬라이드가 있고, 슬라이드의 "그림 개체 틀"에 500문장 삽화(16:9, 1672×941)를 넣는 작업.

**삽화 넣는 방식**
- 삽화는 원본이 장당 ~2.2MB(총 1GB)라 **최적화 JPEG(가로 1400px, q90, 평균 ~240KB)**로 변환해 삽입. JPEG 캐시는 스크래치패드 `jpg_cache`.
- 삽입은 COM 스크립트 `말하기_PPT\_삽화_삽입.ps1`(`-Only 1~4`). 슬라이드의 "N / 500" 번호로 `NNN_*.png` 매칭 → 빈 그림틀에 aspect-fit 후 틀 삭제. 이미지 없는 번호는 틀 그대로 둠. 재실행해도 이미 채운 슬라이드는 건너뜀.
- **테두리는 레이아웃 프레임이 아니라 그림(pic) 자체에 직접** 준다(여백 없이 밀착·직사각형). 방식: pptx zip을 열어 각 slide XML의 `<a:prstGeom prst="rect"><a:avLst/></a:prstGeom></p:spPr>`(테두리 없는 pic 고유 앵커)를 `...</a:prstGeom><a:ln w="15875"><a:solidFill><a:srgbClr val="색"/></a:solidFill></a:ln></p:spPr>`로 치환. 이미 테두리 있는 pic은 앵커가 달라 안 걸림 → 새로 넣은 그림에만 자동 적용됨. 레이아웃의 옛 둥근 프레임(채움 FAF6EC + 점선)은 `<a:noFill/><a:ln><a:noFill/></a:ln>`로 투명화함.
- 테두리색 = 파일별 섹션 deep색(실선 1.25pt=w"15875"): 문장구조 `#466086`, 서술어 `#684C8A`, 부사어 `#586E3C`, 기타 `#A6622A`.

**현재 상태(2026-07-15): 500/500 전량 완료.** 파일1·2·3·4 모두 삽화 삽입+테두리 완료. 마지막 남았던 파일4(기타문법) 391~395(5문장×2슬라이드=10슬라이드)는 2026-07-15에 완성: 사용자가 프롬프트로 5장 생성→폴더 투입, JPEG 최적화(1400×788, q85)→`_삽화_삽입.ps1 -Only 4`로 삽입(10장)→테두리 적용. 이때 테두리는 XML치환 대신 **COM `pic.Line`(Visible/ForeColor.RGB=2777766=#A6622A/Weight=1.25/DashStyle=solid)로 borderless pic만 골라 적용**했고 렌더 확인 결과 기존 슬라이드와 동일. 삽입 전 백업: 스크래치패드 `말하기_4_기타문법_BEFORE_391-395.pptx`.

**그림-문장 일치검사(2026-07-15)**: 500문장 전수검사(10병렬 검수). 482/500 명확 일치. 불일치 1건(291 "가수이면서 영화배우"=다른 두 남자로 그려짐), 개념약화 5건(141 가지맙시다=준비처럼/152 걱정없음=먹구름상충/180 안앉아도됨=권유처럼/258 이틀=하루만/430 열그루=~9그루), 경미 12건. 결과: `_삽화_문장_일치검사_20260715.md`. **A+B 6건(291·141·152·180·258·430) 재생성 프롬프트 작성 완료: `_삽화_재생성_프롬프트_수정6건.md`** — 사용자가 같은 파일명으로 덮어쓰면 교체삽입(기존그림 삭제→새그림→테두리) 예정. 교체작업이라 빈틀채우기 스크립트로는 자동 안 됨.

**삽화 소스 폴더 2곳**: `말하기_PPT\500문장 삽화 최종 20260623`, `놀라운 한국어 500문장 삽화\illustrations`. 롤백 백업은 스크래치패드 `rollback_before_*`.

**환경 주의**: Windows PowerShell 5.1은 스크립트에 **UTF-8 BOM** 없으면 한글 경로가 깨짐(편집 후 항상 BOM 재적용). 한글 파일명은 정규화(NFC/NFD) 불일치로 리터럴이 "not found" 날 수 있어 `Get-ChildItem`으로 FileInfo를 얻어 다룰 것. PowerPoint COM은 저장/열기가 간헐적으로 실패 → 열기 재시도 루프 + 작업 후 XML로 무결성 검증. 관련 [[topik1-haeseoljip-project]].
